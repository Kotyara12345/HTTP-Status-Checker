# HTTP Status Checker

Утилита с графическим интерфейсом для массовой проверки кодов ответа серверов. Принимает до 500 URL за раз, отслеживает цепочки редиректов, измеряет время ответа (TTFB) и умеет прикидываться индексирующими ботами Яндекса, Google и Bing.

## Возможности

- **До 500 URL за раз.** Multiline-ввод, по одному URL в строке. Схема (`http://`/`https://`) опциональна — при отсутствии подставляется `https://` с автоматическим fallback на `http://` при ошибке соединения.
- **Полная цепочка редиректов.** Каждый хоп (`301`, `302`, `303`, `307`, `308`) записывается отдельно со своим кодом и временем. Циклы (`A → B → A`) обнаруживаются мгновенно.
- **Время ответа (TTFB).** Замеряется время до первого байта каждого шага и суммарное по всей цепочке.
- **User-Agent-пресеты.** 18 готовых строк: Яндекс.Бот, YandexImages, YandexMetrika, Googlebot (desktop/smartphone/image), Bingbot, Baiduspider, Applebot, DuckDuckBot и обычные браузеры. Плюс поле для произвольного UA.
- **Rate limiting по хостам.** Задержка между запросами к одному домену настраивается отдельно; запросы к разным доменам идут параллельно.
- **Мгновенная остановка.** Кнопка «Стоп» рвёт активные сокеты через `sock.shutdown(SHUT_RDWR)`, не дожидаясь сетевых таймаутов.
- **Экспорт в CSV.** Порядок строк совпадает с порядком ввода, разделитель `;`, UTF-8 BOM (Excel открывает без кракозябр).
- **Двойной клик по строке** — детальный пошаговый разбор цепочки редиректов в отдельном окне.

## Запуск из исходников

### Требования

- Python **3.10+** (используется синтаксис `int | None`)
- `tkinter` — входит в дистрибутив Python для Windows и macOS; для Linux может понадобиться отдельный пакет

### Быстрый старт

```bash
git clone https://github.com/your-username/http-status-checker.git
cd http-status-checker
pip install -r requirements.txt
python main.py
```

### `requirements.txt`

```
requests>=2.31.0
urllib3>=2.0.0
```

### Установка `tkinter` на Linux

```bash
# Debian / Ubuntu
sudo apt install python3-tk

# Fedora / RHEL
sudo dnf install python3-tkinter

# Arch
sudo pacman -S tk
```

На Windows и macOS `tkinter` уже включён в установщик Python — при установке отметь галочку «tcl/tk and IDLE».

## Сборка портативного `.exe` для Windows

Приложение собирается в один портативный `.exe` через **PyInstaller** — без установки, без записи в реестр, без прав администратора. Готовый файл можно положить на флешку, в облако или передать коллеге.

### Шаг 1. Установка зависимостей

Открой PowerShell или `cmd.exe` и установи всё, что нужно для работы и сборки:

```bash
pip install requests urllib3 pyinstaller
```

Если в системе несколько версий Python и `pip` смотрит не на тот интерпретатор, используй явный вызов модуля:

```bash
python -m pip install requests urllib3 pyinstaller
```

### Шаг 2. Сборка одной командой

Из папки с проектом (там, где лежит `main.py`) выполни:

```bash
python -m PyInstaller --noconsole --onefile --clean --collect-all certifi --hidden-import=urllib3.connection --hidden-import=urllib3.connectionpool --hidden-import=urllib3.poolmanager --hidden-import=idna --name="HTTP_Status_Checker_Portable" main.py
```

Готовый файл появится в `dist/HTTP_Status_Checker_Portable.exe`.

### Разбор флагов

| Флаг | Что делает |
|------|------------|
| `python -m PyInstaller` | Запуск PyInstaller как модуля — работает, даже если `pyinstaller.exe` не в `PATH` |
| `--noconsole` | Не открывать окно консоли. Обязателен для GUI-приложений на tkinter |
| `--onefile` | Собрать всё в один `.exe` вместо папки с зависимостями |
| `--clean` | Удалить кэш предыдущих сборок перед запуском. Убирает ситуацию, когда после правок изменения не подхватываются |
| `--collect-all certifi` | Вложить `cacert.pem` внутрь `.exe`. **Без этого флага HTTPS-запросы упадут с `SSLError: certificate verify failed`** |
| `--hidden-import=urllib3.connection` | `urllib3` использует ленивую загрузку модулей; PyInstaller их в статическом анализе не видит |
| `--hidden-import=urllib3.connectionpool` | То же — модуль подтягивается через `importlib` |
| `--hidden-import=urllib3.poolmanager` | То же |
| `--hidden-import=idna` | `requests` подтягивает `idna` как опциональную зависимость для IDN-доменов |
| `--name="HTTP_Status_Checker_Portable"` | Имя итогового файла. Без `.exe` — расширение добавится автоматически |
| `main.py` | Точка входа приложения |

### Шаг 3. Проверка

Запусти `dist/HTTP_Status_Checker_Portable.exe` и проверь базовые сценарии:

1. **HTTPS-запрос.** Введи `https://ya.ru` и нажми «Запустить». Должен вернуться код `200`. Если увидел `SSLError: certificate verify failed` — значит, забыт флаг `--collect-all certifi`.
2. **Кнопка «Стоп».** Открой 50 URL, нажми «Стоп» через секунду. Окно должно отреагировать за ~200 мс, не залипнуть.
3. **Закрытие окна.** Во время прогона закрой окно. Процесс должен исчезнуть из диспетчера задач за 1–2 секунды.
4. **Портативность.** Скопируй `.exe` в другую папку (или на флешку), запусти оттуда. Всё должно работать без прав администратора.

### Портативность

Собранный через `--onefile` `.exe` содержит внутри Python и все зависимости. Он запускается на любой Windows без установленного Python и не требует прав администратора. Единственный побочный эффект: при каждом старте PyInstaller распаковывает содержимое во временную папку `%TEMP%\_MEIxxxxx`, поэтому запуск занимает 2–4 секунды.

### Размер `.exe`

Минимально возможный размер — 12–18 МБ. PyInstaller анализирует все пакеты, установленные в текущем Python, и может затянуть лишнее. Если в глобальном окружении стоят `numpy`, `pandas`, `matplotlib`, `PyQt5/6`, `scipy` — размер может вырасти до 100+ МБ. Проверить установленное можно так:

```bash
pip list
```

Если видишь крупные пакеты, которые точно не нужны приложению, удали их:

```bash
pip uninstall numpy pandas matplotlib PyQt5 PyQt6 scipy
```

### Альтернативная сборка: `--onedir`

Если антивирус ругается на `.exe` или нужен быстрый старт — собери `--onedir` вместо `--onefile`:

```bash
python -m PyInstaller --noconsole --onedir --clean --collect-all certifi --hidden-import=urllib3.connection --hidden-import=urllib3.connectionpool --hidden-import=urllib3.poolmanager --hidden-import=idna --name="HTTP_Status_Checker_Portable" main.py
```

Результат — папка `dist/HTTP_Status_Checker_Portable/`. Внутри `HTTP_Status_Checker_Portable.exe` и подпапка `_internal/` с зависимостями. Запускать нужно именно `.exe` из этой папки — он ищет зависимости в `_internal/` рядом с собой.

**Плюсы `--onedir`:**
- Запуск быстрый (нет распаковки во временную папку).
- Антивирусы относятся спокойнее — файлы в папке выглядят как обычное приложение.

**Как распространять:** упакуй папку в ZIP:

```powershell
Compress-Archive -Path "dist\HTTP_Status_Checker_Portable" -DestinationPath "HTTP_Status_Checker_Portable.zip"
```

Пользователь распаковывает архив в любую папку и запускает `.exe`.

### Частые проблемы при сборке

| Симптом | Причина / решение |
|---------|-------------------|
| `No module named 'urllib3.connection'` при запуске `.exe` | Не хватает `--hidden-import=urllib3.connection` (или `connectionpool`, `poolmanager`) |
| `SSLError: certificate verify failed` | Забыт `--collect-all certifi`. Без него `cacert.pem` не попадает в `.exe` |
| Антивирус удаляет `.exe` | Собери `--onedir` вместо `--onefile`. Не используй UPX |
| Окно открывается и сразу закрывается | Собери без `--noconsole`, запусти из `cmd.exe` — увидишь traceback. Для отладки: `python -m PyInstaller --onefile --clean --collect-all certifi --name="HTTP_Status_Checker_Debug" main.py` |
| Долгий запуск (5–10 с) | Это `--onefile`: распаковка во временную папку при каждом старте. Решение — `--onedir` |
| `pip` смотрит не на тот Python | Используй `python -m pip install ...` вместо `pip install ...` |
| Сборка падает с `RecursionError` | Редкие глубокие импорты. Добавь `--recursion-limit=5000` |

### Минимальная команда сборки

Если в системе чистое окружение без лишних пакетов, можно обойтись короткой версией:

```bash
python -m PyInstaller --noconsole --onefile --clean --collect-all certifi --name="HTTP_Status_Checker_Portable" main.py
```

`--hidden-import` для `urllib3.*` и `idna` добавляй только если собранный `.exe` падает с `ModuleNotFoundError`.

## Использование

### Ввод URL

Вставь список — по одному URL в строке. Строки, начинающиеся с `#`, игнорируются (удобно для комментариев). Схема не обязательна:

```
ya.ru                          → https://ya.ru, при ошибке https → http://ya.ru
https://example.com            → https://example.com (как есть)
http://legacy-site.example     → http://legacy-site.example (как есть)
```

### User-Agent

Выбери из выпадающего списка или кликни по полю «Свой UA» и введи свой. Выбранный UA применяется ко всем запросам, включая все хопы редиректов одной цепочки.

**Полезные сценарии:**

- **Сравнить поведение сервера для бота и для браузера.** Один прогон с `Googlebot`, второй с `Chrome` — сравни коды в таблице.
- **Проверить клоакинг.** Если `Googlebot` получает `200`, а `Chrome` — `503`, сайт отдаёт ботам подменную страницу.
- **Проверить защиту от парсинга.** `403` для бота при `200` для пользователя = сайт агрессивно фильтрует трафик.

### Задержка и потоки

- **Задержка/хост** — минимальный интервал между двумя запросами **к одному домену**. К разным доменам запросы идут параллельно.
- **Потоков** — сколько URL обрабатывается одновременно. Оптимум: `задержка = 0.3 с`, `потоков = 5` → ~15 запросов в секунду.
- **Connect / Read** — раздельные таймауты. Read-таймаут = максимальная задержка реакции кнопки «Стоп» для задач, уже начавших запрос.

### Метод запроса

- **GET** (по умолчанию) — точнее отражает реальный ответ сервера для браузера. Тело не скачивается благодаря `stream=True`.
- **HEAD** — быстрее, но многие CDN/WAF блокируют HEAD-запросы (`403`, `405`). При `405`/`501` автоматически происходит fallback на GET.

### Результаты

| Колонка | Что показывает |
|---------|----------------|
| `#` | Номер URL в исходном списке (порядок ввода сохраняется) |
| `Исходный URL` | Как было введено (с подставленной схемой) |
| `Код` | Итоговый HTTP-статус (после всех редиректов) |
| `TTFB, с` | Суммарное время до первого байта по всей цепочке |
| `Хопов` | Количество шагов в цепочке редиректов |
| `Финальный URL` | Куда в итоге привёл редирект |
| `Цепочка` | `URL [код] → URL [код] → ...` |
| `Ошибка` | Текст ошибки, если запрос не удался |

**Цветовая подсветка:** 🟢 2xx · 🟡 3xx · 🟠 4xx · 🔴 5xx / ошибка.

**Двойной клик по строке** открывает окно с пошаговым разбором: URL, код и TTFB каждого хопа отдельно.

### Экспорт CSV

Кнопка «Экспорт CSV» сохраняет таблицу с разделителем `;` и UTF-8 BOM. Порядок строк — как при вводе. Колонка `Цепочка` содержит все URL и коды через ` → `.

## Технические детали

### Архитектура

```
┌───────────────────────────────────────────────────┐
│                    App (tk.Tk)                    │
│  UI, валидация ввода, экспорт CSV, диалоги        │
└──────────────┬────────────────────────────────────┘
               │ result_queue ↑     │ start/stop ↓
┌──────────────┴────────────────────────────────────┐
│                 URLCheckerEngine                  │
│  ThreadPoolExecutor, SessionPool, RateLimiter     │
└──────────────┬────────────────────────────────────┘
               │
        ┌──────┴──────┬─────────────┬─────────────┐
        ▼             ▼             ▼             ▼
   check_url    check_url    check_url    check_url
   (worker)     (worker)     (worker)     (worker)
```

`URLCheckerEngine` изолирован от `tk.Tk` — общается только через `queue.Queue` и `threading.Event`. Это позволяет легко тестировать движок без GUI.

### Ключевые решения

- **Ручной обход редиректов** (`allow_redirects=False`) вместо автоматического — нужен для замеров TTFB каждого хопа и построения цепочки.
- **Per-host rate limiter** через резервирование временных слотов. Потоки не сериализуются глобальной блокировкой: каждый атомарно резервирует свой слот, спит вне lock'а.
- **Одна `Session` на поток** (`threading.local()`), с `TrackedHTTPAdapter`. Пул соединений — `2/2` (1 активное + 1 idle), при 50 потоках это 100 структур вместо 500.
- **Прерывание блокирующего `recv()`** через `sock.shutdown(SHUT_RDWR)`. `session.close()` для этого не годится — он очищает только idle-очередь `urllib3`, а активные соединения остаются в `_ConnectionHolder._in_use`.
- **Регистрация сокетов** через кастомный `HTTPAdapter.init_poolmanager`, а не monkey-patch `urllib3`. Глобальное состояние библиотеки не затрагивается.
- **HEAD → GET fallback** при `405`/`501`. `302`/`303` переключают метод на GET по RFC 9110.
- **IDN-домены** (`пример.рф`) явно кодируются в punycode через `idna`.

### Ограничения

- **Не выполняет JS.** Сайты с JS-челленджами (Cloudflare, DDoS-Guard) вернут `403` или `503` независимо от UA. Это не баг — для таких случаев нужен headless-браузер.
- **Поддельные бот-UA видны серверу.** Если сайт проверяет reverse-DNS или ASN отправителя, запрос с UA `Googlebot` с твоего IP получит `403 Fake Googlebot`. Это корректный результат проверки, а не ошибка утилиты.
- **Один UA на прогон.** Чтобы сравнить одну ссылку для нескольких UA, нужно запускать проверку дважды.
- **Лимит 500 URL за раз**.
